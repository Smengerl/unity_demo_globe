## 4. Code dependencies and tools

- **Unity packages** (`Packages/manifest.json`): the packages used (`com.unity.render-pipelines.universal`, `com.unity.inputsystem`, `com.unity.ugui`, `com.unity.test-framework`, IDE integrations) are under the Unity Companion License, which allows use, modification and redistribution **only together with Unity**. It is not an OSI open-source licence. Consequence: this repository can only be used inside Unity projects, which is its purpose anyway. The repository contains none of their source code.
- **Unity Editor**: free for individuals and small companies under Unity's revenue thresholds, otherwise a paid plan. The runtime fee that Unity announced in 2023 was cancelled in 2024; verify the current terms before shipping.
- **Shaders, C#**: all written for this project. The techniques (quintic ramps, hash-based noise, cell grids, Meeus astronomy formulas, Terrarium decoding) are standard published methods; no third-party shader code was copied.
- **HUD icons**: line icons drawn from short SVG path strings written for this project (`Assets/Hud/HudIcons.cs`), not copied from an icon set. As with any simple pictogram (globe, plane, chart) similarity to other sets is possible; they are generic shapes.
- **Python tools**: `numpy` (BSD-3-Clause) and `Pillow` (HPND) are used at build time only.

## 5. Licence of this repository (decided: MIT)

Decision 2026-10-25: MIT, Copyright (c) 2026 Simon Gerlach. The reasoning and the alternatives that were considered:

**Recommendation: MIT** for all own code and own assets, with the third-party material above staying under its own terms.

Why MIT:
- Short, permissive, widely understood in game development; the code can go into the real (closed-source) game without obligations beyond keeping the copyright notice.
- Compatible with everything used here (OFL fonts, UCL packages, public-domain-style NASA data).
- No copyleft burden for users of the globe view.

Alternatives:

| Option | Choose it if | Trade-off |
|---|---|---|
| **MIT** (recommended) | you want maximum reuse and no friction | no patent grant; no protection against closed forks |
| Apache-2.0 | you want an explicit patent grant | longer; requires NOTICE handling |
| MPL-2.0 | you want improvements to the view's files to flow back, but allow use in closed games | file-level copyleft; some friction |
| All rights reserved (no licence) | the repository stays private and the code may become part of a commercial product | others may not legally use it, even if it goes public by accident |

If the repository stays private, no licence is required, but adding one now is harmless and makes a later publication clean. Whatever is chosen, the textures keep their credit lines (section 2) and the fonts their OFL notices.

Suggested file header for the licence: `Copyright (c) 2026 Simon Gerlach` (adjust to the legal owner). Place a `LICENSE` file in the repository root and replace the last line of the README's credits section.

## 6. Publishing the repository and using Unity Personal

Checked against Unity's published terms on 2026-10-25 (sources at the end). Unity changes its terms from time to time, so re-check before release.

**Is it allowed to develop and publish this repository with Unity Personal?** Yes.
- Unity Personal is free for individuals and small organisations with **less than USD 200,000 revenue and funds raised in the last 12 months**; commercial use is allowed under that limit ([Unity Personal](https://unity.com/products/unity-personal)). A free open-source demo earns nothing, so the limit is irrelevant for publishing it.
- The repository contains **no Unity Editor or engine files, no package source code and no binaries**: only own code, shaders, data, `ProjectSettings`, `Packages/manifest.json` and `.meta` files. Redistributing project files like these is common practice and is not a redistribution of Unity software. The package sources are fetched by Unity itself when the project is opened.
- `Assets/Settings/*`, `Assets/InputSystem_Actions.inputactions` and `ProjectSettings/*` are configuration generated by Unity's URP template. They are plain settings data and are normally committed to Unity repositories. If you want zero doubt, they can be regenerated by a fresh template project and removed from the repository; they are not needed for the globe view's own code.
- You own the content you create with Unity ([Unity Personal FAQ](https://unity.com/products/unity-personal)); Unity does not claim rights to your code or assets.

**May someone build a (possibly paid) mobile game from the repository?** Yes, on these conditions:
- **Their own Unity plan applies, not yours.** Whoever builds and sells the game needs a Unity licence that fits *their* revenue and funding: Unity Personal while they stay under USD 200,000 (Unity then requires Pro). The repository's publisher is not responsible for that, but the README says so to avoid surprises.
- Android and iOS builds with Unity Personal are allowed; the restriction listed for Personal is on closed console platforms (Switch, PlayStation, Xbox), which need Pro or a platform-holder licence key.
- Unity's former per-install Runtime Fee was cancelled in 2024; Personal was exempt anyway. A splash screen is optional for projects made with Unity 6 (announced September 2024).
- The **Unity Companion License** of the packages allows use in connection with the Unity engine, including shipping them inside a paid game. The one thing to avoid: modifying the packages' own source and redistributing it, because Unity owns modifications to its package code. This repository does not modify any package.
- Paid use of the **MIT-licensed code** is permitted if the licence is added (section 5); they must keep the copyright notice.
- **Data and fonts:** commercial use is fine, with credit lines for NASA, the terrain data sources and the OFL notice for the fonts. In a shipped game these belong on a credits/licences page; **the in-app licences page is still to do** (see README).
- **Terrain attribution** has not been verified source by source (section 2). A commercial publisher should check <https://github.com/tilezen/joerd/blob/master/docs/attribution.md> or re-generate the terrain textures from SRTM only (public domain).
- Trademarks: the repository must not use Unity's logo or imply endorsement; it does not.

**Residual risks / not checked**
- Not legal advice; Unity's Terms of Service apply to the person using the Editor, and I could not read the full ToS text, only the published summaries and the Companion License.
- Unity could change pricing or terms later; the GitHub copy of your code is unaffected, but a user's right to use Unity is governed by the terms valid when they use it.
- If the author is employed, check the employer's rules on side projects before publishing.
